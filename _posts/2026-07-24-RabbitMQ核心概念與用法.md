RabbitMQ：**message broker（訊息代理）**，居中轉發訊息，讓送訊息與收訊息的程式不用互相認識。用途：**解耦**、**非同步**（送出不等對方處理完）、**削峰**（流量暴增先排隊）。

## 核心概念與訊息流

```
Producer → Exchange →（Binding）→ Queue → Consumer
```

- **Producer（生產者）**：送出訊息的一方。
- **Exchange（交換機）**：收訊息、依規則決定丟到哪些 Queue，本身**不存**訊息。
- **Queue（佇列）**：存放訊息、等 Consumer 來取的緩衝區。
- **Binding（綁定）**：Exchange 與 Queue 的連結規則，決定哪些訊息進這個 Queue。
- **Routing Key（路由鍵）**：訊息帶的字串標籤，Exchange 用它比對 Binding。
- **Consumer（消費者）**：從 Queue 取出並處理訊息的一方。

Producer 不知道訊息最後進哪個 Queue，只丟給 Exchange，由 Exchange 與 Binding 決定去向——這就是解耦。

## 四種 Exchange 類型

| 類型 | 路由行為 | 適用場景 |
| --- | --- | --- |
| `direct` | Routing Key **完全相等**才送到對應 Queue | 依明確類別分流，例如 `error` / `info` 日誌分開處理 |
| `fanout` | 忽略 Routing Key，**廣播**給所有綁定的 Queue | 一則訊息要通知很多訂閱者，例如即時推播 |
| `topic` | Routing Key 依**萬用字元**比對（`*` 一個詞、`#` 多個詞） | 依主題彈性訂閱，例如 `order.*.created` |
| `headers` | 不看 Routing Key，改比對訊息的 **header 欄位** | 需要用多個屬性組合條件路由時 |

入門最常用 `direct` 與 `fanout`。

## 最小可用範例（Python pika）

用 [pika](https://pika.readthedocs.io/) 示範一送一收。先啟動 RabbitMQ：`docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management`。

```bash
pip install pika
```

**Producer（送訊息）**：

```python
import pika

# 連線到本機 RabbitMQ（預設埠 5672）
conn = pika.BlockingConnection(pika.ConnectionParameters("localhost"))
channel = conn.channel()

# 宣告一個 queue；durable=True 讓 queue 在 broker 重啟後仍存在
channel.queue_declare(queue="hello", durable=True)

# 送一則訊息；這裡用預設 exchange（空字串），routing_key 直接指定 queue 名稱
channel.basic_publish(
    exchange="",
    routing_key="hello",
    body="Hello RabbitMQ",
    properties=pika.BasicProperties(delivery_mode=2),  # 2 = persistent，訊息也持久化
)
print("已送出")
conn.close()
```

**Consumer（收訊息）**：

```python
import pika

conn = pika.BlockingConnection(pika.ConnectionParameters("localhost"))
channel = conn.channel()
channel.queue_declare(queue="hello", durable=True)

def callback(ch, method, properties, body):
    print("收到:", body.decode())
    # 處理完後手動回報 ack，RabbitMQ 才會把這則訊息刪掉
    ch.basic_ack(delivery_tag=method.delivery_tag)

# auto_ack 預設為 False，代表採用手動 ack
channel.basic_consume(queue="hello", on_message_callback=callback)

print("等待訊息，按 Ctrl+C 結束")
channel.start_consuming()
```

先跑 Consumer 再跑 Producer 即可收到訊息。

## 常用實務要點

- **持久化（durable + persistent）**：`queue_declare(durable=True)`（Queue）＋訊息 `delivery_mode=2`（persistent）要**同時**設定，broker 重啟才不掉資料。
- **手動 ack（acknowledgement）**：處理完才呼叫 `basic_ack`；Consumer 中途當機沒 ack，訊息會重新派給別人，避免掉訊息。
- **prefetch / QoS（預取數量）**：`channel.basic_qos(prefetch_count=1)` 限制一次只發 1 則未 ack 訊息，讓訊息平均分給多個 Consumer。
- **Management UI**：`http://localhost:15672`（預設 `guest` / `guest`）查看 Queue、訊息堆積、連線與流量。
