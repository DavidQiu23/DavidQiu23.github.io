AES256-GCM：應用最廣的對稱加密方案之一，TLS、JWT (JWE)、資料庫欄位加密背後常是它。這篇整理核心概念與 .NET 範例。

## AES-256 是什麼

- **AES (Advanced Encryption Standard)**：**對稱加密 (Symmetric Encryption)**，加密與解密用**同一把金鑰**。相對 RSA 的非對稱加密，速度快得多，適合大量資料。
- **區塊加密 (Block Cipher)**：一次處理固定 128 位元 (16 bytes) 區塊。
- **256**：金鑰長度 256 位元 (32 bytes)，越長越難暴力破解；另有 AES-128 / AES-192。

## GCM 模式與 AEAD

AES 本身只定義「如何加密一個 16-byte 區塊」，加密長資料要搭配**加密模式 (Mode of Operation)** 串接區塊（CBC、CTR、GCM…）。

**GCM (Galois/Counter Mode)** 是一種 **AEAD (Authenticated Encryption with Associated Data，帶關聯資料的認證加密)**，同時提供：

- **機密性 (Confidentiality)**：內容被加密，第三者看不懂。
- **完整性與真實性 (Integrity & Authenticity)**：資料被竄改，解密時會被偵測。

傳統 **AES-CBC 只提供機密性**，要另配 HMAC 才能驗證，且易實作錯誤（如 padding oracle）。GCM 把加密與驗證整合，更安全也更簡潔。

## 三個關鍵元素

| 元素 | 常見長度 | 角色 |
| --- | --- | --- |
| **Key (金鑰)** | 32 bytes (256-bit) | 加解密的核心秘密，必須嚴格保密。 |
| **Nonce / IV** | 12 bytes (96-bit) | 「一次性數字」，每次加密都要不同，確保相同明文不會產生相同密文。**不需保密**，可與密文一起儲存或傳輸。 |
| **Tag (驗證標籤)** | 16 bytes (128-bit) | 加密時產生，解密時用來驗證資料完整性。竄改後 Tag 對不上，解密即失敗。 |

**Nonce** (Number used once) 最容易被誤用，見下方安全重點。

## C#/.NET 程式範例

.NET 內建 `System.Security.Cryptography.AesGcm`，免額外套件。加密與解密流程：

```csharp
using System.Security.Cryptography;
using System.Text;

public static class AesGcmDemo
{
    // Tag 長度固定使用 16 bytes (128-bit)，安全性最高
    private const int TagSize = 16;
    private const int NonceSize = 12; // GCM 建議的 nonce 長度

    // 加密：回傳 nonce、密文、tag，通常會一起打包儲存/傳輸
    public static (byte[] nonce, byte[] cipherText, byte[] tag) Encrypt(
        byte[] key, string plainText, byte[]? associatedData = null)
    {
        var plainBytes = Encoding.UTF8.GetBytes(plainText);

        // 每次加密都產生全新的隨機 nonce，這是安全關鍵
        var nonce = RandomNumberGenerator.GetBytes(NonceSize);
        var cipherText = new byte[plainBytes.Length]; // GCM 密文與明文等長
        var tag = new byte[TagSize];

        // .NET 8 起建構子需指定 tag 長度
        using var aesGcm = new AesGcm(key, TagSize);
        aesGcm.Encrypt(nonce, plainBytes, cipherText, tag, associatedData);

        return (nonce, cipherText, tag);
    }

    // 解密：若資料被竄改或 tag 不符，會拋出例外
    public static string Decrypt(
        byte[] key, byte[] nonce, byte[] cipherText, byte[] tag, byte[]? associatedData = null)
    {
        var plainBytes = new byte[cipherText.Length];

        using var aesGcm = new AesGcm(key, TagSize);
        // 驗證失敗時會拋出 AuthenticationTagMismatchException
        aesGcm.Decrypt(nonce, cipherText, tag, plainBytes, associatedData);

        return Encoding.UTF8.GetString(plainBytes);
    }
}
```

呼叫範例：

```csharp
// 金鑰應由安全來源取得，這裡僅為示範隨機產生
byte[] key = RandomNumberGenerator.GetBytes(32); // AES-256 = 32 bytes

var (nonce, cipherText, tag) = AesGcmDemo.Encrypt(key, "機密訊息：帳號密碼");
string result = AesGcmDemo.Decrypt(key, nonce, cipherText, tag);

Console.WriteLine(result); // 機密訊息：帳號密碼
```

`associatedData` (AAD，關聯資料)：選用，參與驗證但**不被加密**，適合「綁定但公開」的資訊（訊息標頭、版本號）。加解密雙方的 AAD 必須一致，否則驗證失敗。

## 實務安全重點

{: .notice--danger}
> **Nonce 絕不可在同一把金鑰下重複使用。** 這是 GCM 最致命的誤用：同一把 key 用同一個 nonce 加密兩筆資料，攻擊者就能推導出資訊、甚至偽造驗證標籤，直接摧毀整套加密的安全性。務必每次加密都產生全新的隨機 nonce (或使用嚴格遞增的計數器)。

{: .notice--warning}
> **Tag 驗證失敗時，一律視為解密失敗。** 千萬不要「先輸出明文再驗證」——`Decrypt` 拋出例外時，代表資料不可信，應直接捨棄，絕不能把未通過驗證的內容交給後續流程使用。

{: .notice--info}
> **金鑰要由安全來源產生與保管。** 使用 `RandomNumberGenerator` 這類密碼學安全的亂數來源產生金鑰，並存放於金鑰保管服務 (如 Azure Key Vault、AWS KMS) 或環境變數，**絕不要寫死 (hard-code) 在原始碼或版控中**。
