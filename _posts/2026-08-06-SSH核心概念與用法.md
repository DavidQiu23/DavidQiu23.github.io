SSH 在不可信的網路上連到遠端下指令。

## 最基本的用法

```bash
ssh david@192.168.1.10          # 連線，接著輸入該帳號在遠端的密碼
ssh -p 2222 david@192.168.1.10  # 遠端不是預設的 22 埠時
exit                            # 離開，回到本機
```

連上後看到的是遠端機器的 shell。之後打的每個指令都在遠端執行。

傳檔案用 `scp`，語法是 `scp 來源 目的地`，遠端側寫成 `帳號@位址:路徑`：

```bash
scp report.pdf david@192.168.1.10:~/         # 本機傳到遠端家目錄
scp david@192.168.1.10:~/log.txt .           # 遠端拉回本機目前目錄
scp -r mydir david@192.168.1.10:~/           # 整個目錄要加 -r
```

會用大概就這些。以下是它背後在做什麼，以及怎麼改成免密碼登入。

## 「安全」是三件事

| 目標 | 沒有它會怎樣 | 機制 |
| --- | --- | --- |
| **機密性** | 內容被看光 | 金鑰交換 + 對稱加密 |
| **完整性** | 封包被改，雙方不知 | 封包驗證碼 |
| **身分** | 連到冒牌伺服器，或被人冒充登入 | 主機金鑰 + 使用者金鑰 |

## 一、機密性

對稱加密夠快，適合整條連線。問題只有一個：密鑰怎麼給對方。

**金鑰交換（key exchange）**：雙方各留一份私密資料、各送一份公開資料，然後各自算出同一個值。旁觀者看得到所有公開資料，但缺私密部分，算不出來。

算出的值推導成 **session key**，之後所有封包用它加密。

- session key 每次連線重新產生，結束即作廢，不存檔
- 所以單次被破解不影響其他次連線
- 金鑰交換只保證旁觀者算不出密鑰，**不保證對面是誰**——那是身分的事

## 二、完整性

加密不防改。攻擊者看不懂密文，但翻轉幾個位元就能讓解密結果變樣，而收方會照收。

所以每個封包都附一段驗證碼，用雙方共知的密鑰算出來。收方重算比對，不符就斷線。攻擊者沒那把密鑰，改了就算不出對的驗證碼。

封包序號也算進去，連「重放舊封包、調換順序、偷刪封包」一起擋掉。

## 三、身分

兩個方向，兩套獨立的公私鑰。原理相同：**私鑰能簽、公鑰能驗、公鑰推不回私鑰**。

| 方向 | 金鑰 | 位置 |
| --- | --- | --- |
| 客戶端確認伺服器 | 主機金鑰 (host key) | 伺服器 `/etc/ssh/ssh_host_ed25519_key` |
| 伺服器確認使用者 | 使用者金鑰 | 本機 `~/.ssh/id_ed25519` |

### 確認伺服器：known_hosts

金鑰交換時，伺服器用主機私鑰簽 exchange hash（整段交換過程的雜湊），客戶端驗簽。

驗過只代表「對面握有那把主機私鑰」。中間人送自己的公鑰、用自己的私鑰簽，一樣過。所以要比對 `~/.ssh/known_hosts`：

- **第一次**：無紀錄可比，印出 fingerprint（公鑰雜湊縮寫，短到可肉眼比對）問你收不收。yes 就記進 `known_hosts`
- **之後**：收到的主機公鑰跟檔案裡那把比對，一樣才繼續

{: .notice--warning}
> `REMOTE HOST IDENTIFICATION HAS CHANGED` = 對面換人了。可能是重灌、換機、IP 回收，也可能是中間人。刪掉 `known_hosts` 那行就能連，但那是親手放棄這道防線。

### 確認使用者：authorized_keys

| 檔案 | 放哪 | 用途 |
| --- | --- | --- |
| `id_ed25519` | 只留本機 | 簽章 |
| `id_ed25519.pub` | 伺服器 `~/.ssh/authorized_keys` | 驗章 |

公鑰可以公開，因為它只能驗、不能簽，也推不回私鑰。私鑰外洩則等於鑰匙被複製。

認證流程（私鑰全程不離開本機，送出去的是簽章）：

1. 客戶端問：我有這把公鑰，收不收
2. 伺服器翻 `authorized_keys`，沒有就拒絕
3. 客戶端用私鑰簽一段資料。簽的內容綁定本次連線，錄下來也重播不了
4. 伺服器用 `authorized_keys` 裡的公鑰驗簽

## 連線順序

| 順序 | 動作 | 目標 |
| --- | --- | --- |
| 1 | TCP 連 22 埠，交換版本字串 | —（明文） |
| 2 | 協商演算法 | —（明文） |
| 3 | 金鑰交換產出 session key，**同時**伺服器簽章、客戶端比對 `known_hosts` | 機密性 + 身分 |
| 4 | 之後封包加密並附驗證碼 | 機密性 + 完整性 |
| 5 | 使用者金鑰簽章認證 | 身分 |
| 6 | 開 channel 跑 shell / scp / 轉發 | — |

第 6 步的 channel 可以多開，所以 shell、`scp`、轉發共用同一次握手。

## 範例：設定免密登入

```bash
# 1. 本機產一對金鑰
ssh-keygen -t ed25519 -C "david@laptop"
# 產出 ~/.ssh/id_ed25519（私鑰，留著）與 id_ed25519.pub（公鑰，要送出去）

# 2. 公鑰送上遠端，寫進對方的 ~/.ssh/authorized_keys
#    這一步還是用密碼登入，之後就不用了
ssh-copy-id david@192.168.1.10

# 3. 登入。這次走金鑰認證
ssh david@192.168.1.10
```

第一次執行第 2 步時會先出現這段：

```
The authenticity of host '192.168.1.10' can't be established.
ED25519 key fingerprint is SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

這是伺服器身分那關——本機的 `known_hosts` 沒有這台的主機公鑰，只能由你確認一次。輸入 yes 後記錄下來，第 3 步就不會再問。

對照三個目標：`ssh-copy-id` 送的是**公鑰**（送錯成私鑰就完了），fingerprint 確認的是**伺服器身分**，第 3 步能免密碼是因為客戶端改用**私鑰簽章**證明身分。

## ssh-agent 是什麼

產金鑰時可以給私鑰設一組**通關密語（passphrase）**。設了之後，磁碟上的私鑰檔是加密的——就算被偷走，沒有密語也用不了。代價是每次連線都要輸入一次。

`ssh-agent` 就是為了消掉這個代價：它是一個常駐行程，把解密後的私鑰留在記憶體裡，需要簽章時**由它代簽**。

- 私鑰不會交給 SSH 客戶端，更不會離開本機。agent 只回傳簽章結果
- 只存在記憶體，登出或重開機就沒了，要重新 `ssh-add`
- 沒設通關密語的私鑰其實用不到 agent——反正本來就不用輸入什麼

```bash
eval "$(ssh-agent -s)"        # 啟動 agent 並設好環境變數
ssh-add ~/.ssh/id_ed25519     # 輸入一次密語，交給 agent 保管
ssh-add -l                    # 看 agent 手上有哪些金鑰
```

多數桌面環境（GNOME、macOS）開機時已經幫你起好 agent，直接 `ssh-add` 即可。

## 指令小抄

```bash
ssh-keygen -t ed25519 -C "david@laptop"   # 產金鑰，RSA 只在對方不支援時才用
ssh-copy-id david@192.168.1.10            # 公鑰送上遠端，順便修好權限
ssh -v david@192.168.1.10                 # 除錯，-vvv 更詳細
```

`~/.ssh/config` 把參數存成別名，設好後打 `ssh myserver` 即可：

```
Host myserver
    HostName 192.168.1.10
    User david
    Port 22
    IdentityFile ~/.ssh/id_ed25519
```

權限太寬鬆 SSH 會拒用，且不明講原因：

| 路徑 | 權限 |
| --- | --- |
| `~/.ssh` | `700` |
| `~/.ssh/id_ed25519` | `600` |
| `~/.ssh/authorized_keys` | `600` |

## 連不上時看哪裡

| 訊息 | 意思 | 通常要查 |
| --- | --- | --- |
| `Connection refused` | 對方機器活著，但 22 埠沒人聽 | sshd 服務沒啟動，或 port 不是 22 |
| `Connection timed out` | 封包根本沒到 | IP 打錯、機器沒開、防火牆擋掉 |
| `Permission denied (publickey)` | 連得上，但金鑰認證沒過 | 公鑰沒進遠端 `authorized_keys`，或本機沒帶對私鑰 |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | 主機公鑰跟 `known_hosts` 對不起來 | 先確認遠端是不是真的重灌過 |

分不出來就 `ssh -v`，輸出會照〈連線順序〉那張表往下走，停在哪就是哪一步出事。
